# Show protocol (v1)

The show engine (the show page) owns all game state. Remotes (the presenters' tablet, the admin phone, and later a split-mode drum or audio device) send **commands** and render the engine's **events**. Messages travel as JSON over the relay's WebSocket (`/ws`). The engine checks every command on arrival, and a command that fails the check is rejected, never thrown.

The package `@quina/protocol` (`packages/protocol/`) is the source of truth, and this page explains it. It imports no engine code, so any remote, the player app or a Worker can import it:
- `vocabulary.ts`: the shared words and constants. `PROTOCOL_VERSION`, `PhaseName`, `ShowStatus`, `ShowScene`, `WinKind`, the Claim and Check words, the recipe names, the Pace limits and presets, the sound names, the reject reasons and the relay roles.
- `commands.ts`: `COMMANDS`, the field spec every arriving command is checked against, plus `checkCommand` and `makeCommand`. The `Command` type is derived from the spec, as a discriminated union on `cmd`, so the documented fields and the checked fields cannot drift apart.
- `events.ts`: every event as a discriminated union on `type` (`ShowEvent`, `IncomingEvent` with the relay's client list), `ShowState`, `makeEvent` and `isEvent`.
- `journal.ts`: the Game journal (below), its entries, `GameRecord`, `replayJournal` and `extendJournal`.
- `plan.ts`: the Game plan (below), the setup Admin edits, and `checkGamePlan`.
- `public.ts`: the public feed for players' phones (below): `PublicState`, its changes, the `applyPublic` reducer and `followFeed`, and the phones' reconnect rules.

- **Versioning.** Every message carries `v: 1`. The relay drops messages with a different version, and so does the engine. New commands and events are additive and stay v1: the engine rejects a command it doesn't know as `unknownCommand`, and remotes ignore event types they don't handle. Only a breaking change bumps `v`, because the relay would then make every device reload together.
- **Time.** Every time is in **epoch milliseconds** (`…AtMs`). Devices share timestamps, never an audio clock (ADR 0002), so a remote computes countdowns locally from `landAtMs`, `autoAtMs` and the like.
- **Terms.** Messages use the words from `GLOSSARY.md`: Hook, Landing, Spin, Pace, Hold, Hold music, Back, Phase, Heat, Queue, Cards in play, Shuffle, Tie, Claim, Check, Winner, Celebration, Interval.

|---|---|---|

| `{ v, type: 'relay.mode', test }` (`RelayMode`, protocol events.ts; `relayModeMessage`, relay/gate.ts) | relay → every paired client, right after its hello | Whether the relay runs in test mode (`--test`, rehearsal test runs only, never on the night): always sent, `test: false` without the flag. | `{ v, type: 'remote.status', connected, battery, sinceMs, drops?, lastDropMs?, clientId? }` (`drops`: disconnections in the host's last 10 minutes; `lastDropMs`: the latest, or null) | the console hosting the Wii Remote → relay → the other paired consoles (tablet, admin) | The remote's status (`readRemoteStatus`, `remoteStatusMessage`). **Who may say what.**
- **Binding:** the relay listens on this laptop only unless it is started with `--lan`.
- **Laptop-only roles:** `show` and `cloud` are accepted only from this laptop.
- **Pairing:** a device on the hotspot (`tablet`, `admin`, `drum`) pairs with the relay token. The token is printed at start as part of the LAN URL (`?t=…`), kept in `data/cache/relay-token`, and can be overridden with `--token` or `QUINA_RELAY_TOKEN`.
- **Unpaired sockets:** a socket without a valid hello hears nothing.
- **Events:** they come only from the show socket. The Game journal (`journal.entry`, `journal.entries`: Queue, seeds, names) goes only to `cloud`. Every other event goes to the paired remotes and the link, and a newly paired one gets the last `state`.
- **Commands:** they come only from `tablet`, `admin` and `cloud`, and go to the show, stamped with the sender's clientId (`from`; through the cloud, the cloud console's `cloud:<id>`). `getJournal` comes only from `cloud`. The test tools (`TEST_COMMANDS`: `testReset`, `testJump`) go through only when the relay runs with `--test`, and never from `cloud`, even then: a console through the cloud can't reset or jump the show. One pure function says all of it (`relayAcceptsCommand`, relay/gate.ts).
- **Test mode (`--test`):** rehearsal test runs only, never on the night. The relay prints a banner saying so as it starts, and tells every paired socket (`relay.mode`).
- **Cloud consoles:** `cloud.consoles` comes only from `cloud`; it goes out only folded into `relay.clients`.
- **This laptop only:** `/api/*` (hook overrides, stretch renders) and `/cloud/` (except `plan.json`) answer only to this laptop.
- **The Game plan (relay/plan.ts):** `/cloud/plan.json` is public: the newest of the cloud link's `cloud-plan.json` and a plan saved on the laptop's network (`local-plan.json`), both `{ savedAtMs, plan }` in the link folder; it is pushed as `relay.plan`. `GET`/`PUT /api/plan` answer this laptop and devices paired with the token (`authorization: Bearer <token>`); PUT is plan B's save with no cloud: checked with `checkGamePlan` (and the cloud copy's edition), at most 512 KB, answered like the cloud's `/api/plan` plus `savedAtMs`. When the cloud is back, the link sends a newer local save up (`link.plan`); the cloud keeps the newest, and the local file goes.
- **Admin's images:** the link copies the plan's `/media/<key>.png|.jpg` (and each one's JPEG XL, when uploaded) into `data/link/media/`, and the relay serves them publicly at `/media/`, immutable. Like the cloud, a `.jxl` with no JPEG XL answers with the fallback's bytes.

## Commands

`{ v: 1, type: 'cmd', cmd, reqId, from?, ...fields }`. `reqId` is any unique string; a rejection quotes it back. `from` is the sender's clientId: the relay stamps it on every command it forwards (`stampCommandFrom`), replacing any the sender set, so a console can't speak for another; the show page's own carry none. The one exception is the cloud link's socket (`stampCommandFrom(…, { viaCloud: true })`): the cloud stamps each of its consoles' commands `from: 'cloud:<that console's hello clientId>'`, and the relay keeps a `from` that is `cloud:` and a plain id (1–64 of `[A-Za-z0-9_-]`, `isCloudConsoleId`), so every console through the cloud is its own sender; any other `from` there becomes the link's clientId (an older cloud's commands all count as the link's). On every other socket even a `cloud:` `from` is replaced, so no LAN console can pose as a cloud one. Only `twoLevelHold` and the lock it sets on `hold`, `suspense` and `pause` read it.

## Scenes

The scene is where the show is in the Game; `status` stays the audio state underneath. A Hold while the presenters talk is `play` with `status: 'hold'`, so the projector shows no change. `packages/protocol/scenes.ts` holds the rules (`SCENE_RULES`, `sceneAllows`), shared with the remotes; the engine rejects any other command as `wrongScene`.

| Scene | Accepts, besides the commands allowed everywhere* | Leaves by |
|---|---|---|
| `before` | everything `play` accepts except `claim`, plus `roundIntro` and `throw` | the first Spin → `play`; `roundIntro` → `roundStart`; `newRound` → `roundStart` |
| `roundStart` | `newRound`; once the Shuffle is drawn, `next` (it waits for the animation) | the Shuffle's end → `play` |
| `play` | `next`, `back`, `hold`, `holdMusic`, `suspense`, `confirmLine`, `newRound`, `claim`; in the night's last round `storm` (D155) | `claim` → `check`; `newRound` → `roundStart` |
| `check` | `claim`, `checkStart`, `checkNext`, `checkBack`, `checkAuto`, `checkReview`, `reviewEnd`, `back`, `holdMusic`; under review `hold` (D118); in the night's last round `storm` | the last cue → `celebration` (or `celebrationNext` and one more press), `play` (`checkFailed`, its ✗ on screen for `FLOW.check.nextCardSec` first, or `discarded`) or the interrupted Celebration |
| `celebration` | `claim`, `celebrationMusic`, `confirmLine`, `newRound`, `hold` (Parlem ducks its music, D117); a Line's: `next`; a Bingo's (or the last card standing's): `interval`, `roundIntro` | Line: `next` / `hold {on: false}` → `play`. Bingo or last card standing: `interval` (or by itself after 60 s), `roundIntro` |
| `interval` | `roundIntro`, `newRound`, `intervalSkip`, `throw` | rounds always start by hand |
| `after` | `roundIntro`, `newRound` (so an `endGame` by mistake can be undone), `intervalSkip`, `throw`, `storm` | |

`storm` in `play` and `check` follows `SceneContext.lastRound` (the state's `lastRound`); without it the rules allow it only in `after`.

\* Allowed everywhere: `unlock`, `getState`, `getJournal`, `setPace`, `setGame`, `setVolume`, `setCardsInPlay`, `addCardsInPlay`, `sfx`, `overrideNextRecipe`, `panic`, `pause`, `endGame`, `winnerInfo`, `revealPrizes`, `twoLevelHold`, and the test tools `testReset` and `testJump` (test runs only: Commands › Test runs). During Pausa only these go through, plus `next` and `intervalSkip` where their own rules allow them.

`intervalSkip` follows the music rather than the scene: `SceneContext.intervalMusic` (the state's `intervalMusic` is not null) allows it, also in `play` after the Shuffle until the first Spin builds out of the music, and during Pausa (the Pausa set). Without it the rules assume a set plays in `interval`, `after` and during Pausa.

- **A fresh Game starts in `before`**, and `before` accepts every command `play` accepts today, so nothing that worked before the show flow is rejected. Round 1's Queue is drawn when the show page starts (no public Shuffle); the first Spin moves the scene to `play`. To run the public Shuffle instead, the presenters send `roundIntro` (optional) and `newRound`.
- **Shuffle.** `newRound` draws a secret seed from the secure generator and reshuffles deterministically (draw 0, 1, 2… of the seed, `engine/src/game/shuffle.ts`) until neither the first Line nor the first Bingo is a Tie among the cards in play valid for the round (those of its card type). With no cards in play the first draw is kept. After `FLOW.shuffleMaxAttempts` (500) draws it keeps the last and logs a warning. The seed and the number of reshuffles are journaled (`round.started`). The projector gets only `shuffle.scheduled` (never the Queue), and no song lands before its `endAtMs` (`FLOW.shuffleSec`, 8 s). A fixed Queue (tests, `?queue=`) bypasses the tie check: seed 0, attempts 0.
- **The Desgraciat round** (`kind: 'desgraciat'`, one per night): played in reverse. A card falls when one of its songs lands, and the last card standing wins (a `standing` Claim, celebrated like a Bingo: the victory track, then the Interval). A landing that would take out every card still standing counts for none of them (D180): they all stay in, so exactly one card is always left last and there is never a shared win. Its Shuffle keeps its first draw (rule `none`: nothing can tie). Its Phase follows the count of valid cards still standing, which the room sees anyway: `mid` from 15, `late` from 6, `final` from 3 (`STANDING_MODEL_DEFAULTS`, tuned with `tests/support/desgraciat.ts`), the Heat rising within each band as the count falls. Auto-advance never takes out the last card: it stops once one stands. The console gets the standing cards (`standing`, PRIVATE) and the Futur's `lastStandingAt` / `standingCurve`; `possibleWinners` stays empty, and `confirmLine` is `invalid`.
- **Check.** The engine computes it from the card (any generated card), the kind claimed and the counted landings now: `unknownCard` (a number outside the generated cards) and `wrongType` (a card of another type than the round's `cardType`) have no steps and show at once; `notSold` is only a warning. A Line plays its completed row (the first to complete, top on a tie; the others are in `otherRows`), else the row with most landed songs (top on a tie); a Bingo plays all 12. A `standing` claim (the Desgraciat round) plays the card's 12 songs in card order: a card a counted landing took out stops at that song (`fallen`, its last step with `landed: true`); a card still standing plays all 12 (`complete`, `completeSince` the landing that left it the last one, else null). In a standing Check `landed` means counted against the card: a landing that didn't count (D180) shows as not landed. `fellLast` (the shared win) is only in journals from before D180. Each ✓ reveal plays the song from its best hook's pickup and keeps playing it until the next reveal, a step back or the Check's end (its cue, Pausa, Panic, the Check leaving the screen; a Review leaves it playing, D118); it never goes silent: it starts at once on the song's 3 s snippet (`tools/prep/snippets.py`, `/snippets/<id>.flac`) and hands over, sample-aligned and at the same level, to the full song (`/audio/<id>.flac`) once it is decoded, and near the song's end it repeats its last full phrase like any song left playing (D239: 8 bars, else 4, counted from the hook, ending at least `LOOP.stayTailSec` before the end and before its audio dies), else its last 4 bars; only a song with no beat grid jumps back to its pickup with a crossfade. Until the song is decoded, or if it can't be, the snippet itself loops back to its start. The reveal itself lasts 2.5 s (`stepSec`: the automatic reveal's pace). Each ✗ reveal plays its song the same way and at the same level, and `missBreakAfterSec` (2 s) in its tape breaks (`FLOW.check.brokenTape`, audio/fx/broken-tape.ts: a groan down two semitones, then a slow wow, muffled and a little saturated, loudness-compensated) and stays broken, loops included, until the cue (the Failure fanfare and the error Hold music as before; the song fades out under it), a step back or the Check's end; its reveal lasts `missSec` (2.5 s, as a ✓'s: the screens stamp its mark as the tape breaks, and under auto the cue comes that long plus `gapSec` after it). In a standing Check each song not heard yet (its ✓) is a short wood-block knock (`FLOW.check.stillSec`, 0.55 s), and the landed song that sank the card plays its snippet as the proof.
  - **Paced by the presenters (D107):** nothing is revealed until a press (`checkNext`); each press reveals the next song in the card's grid order, cutting the song before it. Auto (`checkAuto`) reveals the next one `stepSec` + `gapSec` after each reveal, through the cue. The reveals stop at the last song or the first ✗ (`revealUntil`); the next press is the cue (`cueNext`).
  - **The music under it:** from the first reveal the song or Hold music is ducked far down (−32 dB, U85 (a) for now) until the cue; back at none (`checkBack`), and between two cards, the music from before the Check comes back up to the Claim's level.
  - **Several cards (D110):** checked in turn. A pass that isn't the batch's last is valid with the plaque and no fanfare; the last cue starts the shared Celebration if any card passed (after a failed last card, one more press: `celebrationNext`), else the fail moment and the round back in its Hold (`checkFailed`).
  - **Back** (`back`, the long press) during a Check undoes the landing; undecided Claims survive (a Claim under review stays under review) and wait for `checkStart`.
- **Celebration.** The Clear fanfare and an impact, then its music: the Winning song's hook (the one it landed on) looped in whole bars for a Line, the victory track (the `celebration` mood of Hold music) for a Bingo. Every valid Claim of that kind in the round shares it (`cardIds`: claims on the same landing share the prize).
- **Interval** (the user's "Break", D136). `interval.guideEndMs` is only a guide. Its music is the **breaks set** (D129: the pop playlist `0fvoRGCC8zXqDyj5uLhJVg`), one of three **music sets** (`MUSIC_SETS`), each a folder `data/media/interval/<set>/` analysed by `tools/prep/interval.py` into `data/out/interval/<set>/`: `breaks` in `interval` and until a round's first Spin, `pausa` (`0XTlZPUpt7xPoPxk4AUU3O`) during Pausa, `end` in `after` (for now the breaks' tracks in their playlist order, U97). A round's intro plays its intro track instead (`roundIntro`), and a set's music builds out of it the same way.
  - **Order:** shuffled per Game and set (seeded from the Game id, so a reload keeps it; how far it got is kept in the page's storage), every track once before any repeats, and a recording only once; the `end` set plays in the playlist's order.
  - **No silence:** the music playing when it starts (the victory track, Hold music after a pause, the Winning song's loop) goes on until the first track is decoded, then echoes out on its own downbeat while the first track comes in on that downbeat. From silence (a fresh page's first `roundIntro`) the first track fades in.
  - **Between tracks:** the outgoing track's last beat goes into an echo synced to its beat on a downbeat 8–12 s before its sound ends (a phrase start when there is one, never more than a second into a closing fade), its dry signal stops on that one, and the echo thins out over 4 s. The next track's downbeat lands on the same one. With tempos within 4% (after ×2 and ÷2), two bars of it rise under the outgoing track first, by a swell (gain and high-pass) or a filter opening (low-pass), the two alternating, while the outgoing track thins out. With tempos apart, only its pickup plays before the one and its low-pass keeps opening for two of its bars, so the two grids never clash. No drum, nothing else: it is the break, under the presenters' talk.
  - **Skip** (`intervalSkip`): the same transition on the playing track's next downbeat. **Volume:** each set's slider (`setVolume`: `breaks`, `pausa`, `end`).
  - It plays on its own bus under the songs (the Hold duck, a Check's duck and a build's high-pass treat it like them), and gives way like Hold music: it fades out from the first Spin's start (+0.2 s, over 1.6 s) while the build comes out of it, or cross-fades to Hold music (the pause, `holdMusic`).
- **Pausa** (D128, D135). Nothing lands (a Spin or Suspense in flight is cancelled, U105; a Check on screen goes back to the queue, U107), the playback in progress is saved and fades out, and the Pausa set plays. "Tornem de seguida" shows only during a round, a Check or a Celebration (`pause.overlay`). Ending it (`pause {on: false}`, the Wii's A) resumes the saved playback exactly where it was, fading in: a song (its loop and timeline shifted by the paused time) under Parlem (Hold reason `pause`), Hold music, the Celebration's music, a set, the throw song, a Check's revealed song (its snippet or full song, its loop, under the Check's duck again; its marks stay and the next reveal waits for a press). A Check that ends during Pausa (a discard, Panic) drops its saved song. Every timer excludes the paused time. Next ends Pausa with that song's transition out of the Pausa music. Panic clears the saved playback.
- **The throw songs** (D138 `throw`, D151 `storm`). Each a setting in `engine/src/config.ts` (`THROW.songs`: its track in `data/media/throw/`, decoded by `tools/prep/hold.py`, and its hook), at full volume (the `throws` slider, a song's loudness) over the scene's music, which fades out under it and back after.

`hold.reason` adds `claim` (a Check, through the Celebration), `checkFailed` (every Claim of the last Check was invalid), `discarded` (a Review discarded: the music from before the Check under Parlem) and `pause` (Pausa ended: what it saved plays again under Parlem). In `celebration`, `interval` and `after` the status is `hold` too: no song lands, the scene's music plays.

`beat` (PUBLIC) lets phones bob the card marks in time with a pure CSS loop, phase-aligned to one downbeat, with no script per frame: period = k · 60000 / `bpm` ms (k beats a cycle, for example `beatsPerBar`), and animation-delay = `downbeatAtMs` > now ? `downbeatAtMs` − now : −((now − `downbeatAtMs`) mod period). `bpm` is the tempo as heard: the median of the song's next 8 bars from the anchor (its analysis' `tempo.bpm` at its very end), times the playback rate; `beatsPerBar` its metre (`tempo.beatsPerBar`); `downbeatAtMs` one of its downbeats, the latest at or before the moment it was sent (engine plan/beat.ts, tunables in config.ts `BEAT`). Only a song of the repertoire counts, as the room hears it: Parlem's ducked song and the voice cues' dips count. During a Spin it is the outgoing song's until its exit move starts (`a.exitStart`: the move bends its time), then already the incoming song's, `downbeatAtMs` = its landing (`landAtMs`, ahead of now: nothing moves before it); a Spin without an outgoing song has it from its start. It never goes out before that Spin's `transition.scheduled` (a phone learns the landing song from it). A landing puts the hook's downbeat exactly there and the song plays on at its own speed, so the landing itself sends nothing new. A held Suspense keeps the outgoing song's while it plays (its phrase loop, or until its exit starts), else null; the incoming song's comes with its release's Spin. A cancelled Spin goes back to the outgoing song's, or null. null: no song (Hold music; scene music: the Interval, the breaks, Pausa's set, a round's intro, the Celebration), Pausa, a Check's reveals (its revealed songs over the music far down, from the first reveal to its cue), or a song with no downbeats. It goes out to every phone, so the engine keeps the value it sent unless it changed materially, and sends the state for it when nothing else did: null ↔ a value, or another song or a moved deck clock (a phrase loop's re-cue, a Pausa resume) at once, unless the new grid is the same one (bpm within 0.2 %, the same metre, its downbeat within 30 ms of the sent grid's, modulo a bar, both moving or both waiting for the same landing); the same deck when its own downbeats drift over 30 ms from the sent grid, at most once every 4 s, and never before a landing's `downbeatAtMs` passes. On the test and 2026 repertoires that is about one new value a minute per song (median), none at all for a steady song.

## Game journal

The Game is what must survive a restart: the round and its Queue, the landings and undos, the confirmed Line, the cards in play and the settings. The engine writes each fact as a numbered journal entry, keeps it in the show page's storage, and emits it as `journal.entry` for anyone keeping a copy. Live playback (the decks, the Spin in flight, the effects) is left out on purpose: after a restart it starts fresh.

| `kind` | Fields | Written when |
|---|---|---|
| `round.resumed` | the same as `round.started`, plus `position, lineConfirmedFrom` | A round resumed by hand (`resumeAt`). The songs up to `position` count from this entry's `atMs`, because their real times are unknown. The Game is in `play`, and the round's Claims and intro are reset |
| `round.started` | `round, roundKind, cardType?, side?, queue, phaseSeed, startedAtMs, targetEndMs, settings, shuffleSeed, shuffleAttempts` | A round starts: its tie-free Shuffle (the Queue is draw number `shuffleAttempts` of `shuffleSeed`; 0 and 0 for a fixed Queue) and the secret seed that blurs its Phase. Every entry also carries `gameId`, `seq` (1, 2, 3… with no gaps within a Game) and `atMs`. `replayJournal(entries)` turns a journal into a `GameRecord`, and every side uses that one reducer, so they all agree. `extendJournal(record, entries)` applies more entries to a record without replaying the history, and gives the same result as replaying the whole journal; the cloud uses it on every upload. Besides the round and its landings, the record keeps the show flow: `scene` and `sceneSinceMs`, `intro` (in `roundStart`, the round introduced), the round's `claims` (`{ claimId, round, cardId, kind, position, atMs, verdict }`, `verdict` null while undecided), `claimCount` (claim ids go on from it: `cl-<n>`) and the Game's `winners` (PRIVATE: `name`, `notes`). `playedBefore` lists the songs counted in the Game's earlier rounds, each once (D174): at `round.started` or `round.resumed` of another round number, the round in progress's Queue up to its last counted landing joins it (`foldPlayed`). A song not in it is a first play. A record kept from before it reads as `[]`. A verdict on an unknown Claim, a Claim decided twice or a Winner's note without a Winner throws a `JournalError` too. A gap, a repeat, another Game's entry or a song that isn't at its Queue index throws a `JournalError`, and nothing is resumed from a wrong state.

**Resuming.** A show page boots into one of these, in this order (`chooseResume` in `engine/src/journal-store.ts`):
1. **Admin's manual resume.** The cloud link's `/cloud/resume.json` is used when it is newer than this page's last local entry. It resumes that Game up to its entry `seq`, from `/cloud/journal/<gameId>.jsonl`.
2. **This page's own journal,** if its last entry is under 12 hours old (`ENGINE.resumeWithinMs`).
3. **The cloud copy's current Game** (`/cloud/current`), if it is recent: a new laptop.

A cloud journal becomes the page's own: new entries continue its numbering, and whatever was stored for that Game moves to an archive key and is never deleted. A broken journal is never resumed from: the console says why, and the next source is tried. Resumed means the same round, Queue, position, landings, Line and settings, with the drum showing the last landing. The status line says "Represa des del núvol" or "Represa des d'aquest portàtil". Nothing plays until Next. `?fresh=1` starts a new Game. A test show with `?queue=` or `?journal=0` keeps its journal in memory only. With no journal anywhere, see "Resuming by hand".

## Resuming by hand (plan B)

On a show page with no journal (a replacement laptop, offline), the presenters resume the round with `resumeAt`.
- **How it works:** the Shuffle is seeded. Its seed, the round's pool and the cards in play give back the exact Queue, and the engine checks that against the token. A token is `{round, kind, cardType, side?, shuffleSeed, shuffleAttempts, position, lastSongId, lineConfirmedFrom}` (the card type picks the cards the Shuffle checked, so the Queue depends on it); `text` is the same as a short code (`packages/protocol/resume.ts`).
- **The code:** for example `Q3N-4K7XM2P-17-S41-L12` is round 3 (normal; `E` the special round, `D` the Desgraciat round), the seed in 7 Crockford base32 characters, the last counted position, the song there, and where the Bingo climb started. A round whose card type isn't its kind's default adds it: `…-TESPECIAL`; a round on a side other than 1 adds `C<side>` last (`…-C2`, D178). `formatResumeToken` and `parseResumeToken` read and write it.
- **State:** the state's `resume` holds the current token. It is PRIVATE: tablets only, never a public screen or a phone.
- **Where the seed comes from, in this order:**
  1. the laptop's local journal (localStorage, or the cloud link's disk copy);
  2. the cloud, if the round started before the connection dropped;
  3. the code an admin noted at the Shuffle. The console shows it on its tucked-away panel. Keep it like the box of cards: with the cards in play it gives the whole Queue.
- **Refusals:** a Queue that doesn't match is refused (`cannotResume`), never resumed. That covers other cards in play, a mistyped seed, position or song, and a different draw number. Without the round's seed, no Queue can match the cards, so there is no resume.
- **What doesn't come back:** a resumed round starts a new Game id, because its earlier journal isn't on this laptop. Its earlier landings count, but their times and the round's Claims don't come back, and nor do the earlier rounds' songs: they count as first plays (D174).

## Pools and sides (D178)

- **Songs (D268):** a repertoire holds every song once, with one id, and each pool lists its songs, so a song can be in several. Each song in the repertoire's songs.json carries `pools` (sorted, one or more pool ids: `["1"]`, `["1", "2"]`); one without it is in pool "1" (a repertoire never split into pools is all pool 1). The old single `pool` is gone (D268's step 3). analyze.py copies `pools` into `analysis/index.json`, which the show reads, `["1"]` for a song without them. 2026: 135 songs; pool 1 has 70 (1–70), pool 2 has 70 (its own 71–135 and 5 of pool 1's: 5, 44, 46, 54, 62).
- **Card types:** apps/cards' card-types.json gives each type `sides: [{ side, pool, label?, mark?, checkLabel?, heading? }]` (`checkLabel`: what the Check shows, D266; `heading`: the printed side's heading) (D193: the normal card's side 1 is pool 1 "1-5", side 2 pool 2 "6-10"; D226: the especial card's side 1 is pool 1 for the Desgraciat, side 2 pool 2 for the Especial, so the pool changes in the Descans). A type without `sides` has one: side 1 on pool 1. `cardTypeSides` and `sidePool` read it; the screens show each side's `checkLabel` as it is (D266).
- **Cards:** cards.json's card is `{ id, type, sides: [{ side, lines }] }`; a card from before sides has `lines`, its side 1. A round counts each valid card's face on its side (`cardFace`); a card printed without that side doesn't count, and its Check is `wrongType`.
- **Rounds:** a round plays one side (`RoundPlan.side`, `roundIntro` / `newRound` / `resumeAt { side? }`, default 1). Its Queue is a tie-free Shuffle of that side's pool's members (a song shared with another pool included), in the repertoire's order; a pool with no songs plays the whole repertoire, with a warning. The side is in `round`, `intro` and `check`, in the journal (`side` on round.started, round.resumed and scene.changed, absent for side 1) and in the resume token.
- **The plan's check:** `sideWarnings(plan, cardTypes, poolSongs?)` lists a round on a side its type lacks, a side no round plays, and a pool without songs, for Admin and the preflight.
- **First plays (D174):** later rounds expect their first plays from their own pool's songs still unplayed. A song in several pools counts in each (`poolsLeft`), and a first play is the Game's, not a pool's: a shared song played in a pool 1 round is no first play when it comes up on pool 2.

## The drum's order and Spins (D237)

The phones lay out and spin the same drum as the projector. A round's tiles are its Queue's songs (its pool's, which are public) in `drumOrder(songIds, drumSeed)` (packages/protocol/drum.ts: sorted by id, then a seeded Fisher–Yates), the ones still to play plus the last landing. `drumSeed` is PUBLIC, journaled on `round.started` and `round.resumed` (drawn on its own, so it tells nothing about the Queue; the record keeps it, and a restart keeps the order). Each Spin's `transition.scheduled` carries a PUBLIC `spinSeed`: with `spinStartAtMs`, `landAtMs`, `drum.minLaps` and the landing tile, `solveSpin` (apps/show/engine/src/wheel/solver.ts, pure) gives the projector's very trajectory. The landing tile stays private until `landAtMs` (U206). Backend projects both seeds for the phones, as `PublicRound.drumSeed` and `PublicSpin.spinSeed`. The engine's state carries it too, as `round.drumSeed` (the same value as the round's `round.started` or `round.resumed`), so the relay's own feed can give it to phones on the venue LAN.

The projector's drum keeps that order all round. A Spin takes the last landing's card off; when a card comes back (Back undoes a landing, and the landing before it returns; or a Spin is cancelled, by Back or Hold, or a Suspense is backed out, and the last landing returns), it goes back at its own place in the order, not where the drum happens to stop. The engine's `drumBack` effect and `cancelTransition`'s `drum` carry `ids`, the drum's cards with it back (`drumOrder(queue, drumSeed)` filtered to the songs still to play and the last landing), with `insertId` the card that returns; the runtime takes that order, keeping the card under the pointer, and moves onto `insertId` at its place (`drum-back`, D249): a Back from rest turns the shortest way onto it, at most half a lap, in one cubic glide from rest (0.9 s for one card, rising evenly to 1.6 s for half a lap); a cancel (or a Back while the drum still moves) brakes naturally, as before (`brakeRest`, in its own direction, no target), and once it's nearly still (1 card/s) glides the short way onto the card (0.8 s for one card, rising to 1.6 s for half a lap, so a far card never whips round faster than a Back). The speed never jumps and never rises while braking. With reduced motion the drum is on the card at once. A Back to before the first landing brings no card back (`insertId` null) and turns back one card, opposite to the last Spin.

## The edition file (D116)

`packages/protocol/edition.ts`: `EditionFile` is `{ v: 1, repertoire, plan, songs: [{ id, title, artist, pools }], cardTypes?, cards? }`, one JSON per edition kept in git and uploaded by hand (tools/edition). `checkEdition(doc)` is the check every reader shares: the plan as `checkGamePlan` reads it; unique song ids, each with a title, an artist and `pools`, a non-empty list of pool ids (D268: a song shared by two pools is listed once, in both); when present, each card's type in `cardTypes`, each side one its type prints, 3 lines of 4 songs that are members of that side's pool; a round on a side its type lacks is an error, a side no round plays or a pool without songs a warning (`sideWarnings`, counting a shared song in each of its pools). The cards stay optional until U68 and U75. `tools/edition/songs.ts` (`editionSongs`) reads the songs from a repertoire's songs.json (`pools`, or `["1"]` for a song without them), each song's `title` and `artist` being its print names (`printTitle ?? title`, `printArtist ?? artist`: the clean names tools/prep/pools.py writes), so every reader shows the clean name with no field of its own.

## Public feed (phones)

Players' phones get the Game from the cloud, never from the relay. The cloud builds a whitelisted projection of what it keeps (cloud/src/domain/projection.ts); `public.ts` types it, and phones and the cloud apply it with the same reducer. Defined by Platform and UI together.

- **Connecting.** `wss://<cloud>/feed?cards=12,123`: the phone's card numbers (`cardsParam`; at most `PUBLIC_FEED.maxCardsPerPhone`), which feed Admin's anonymous "cards opened on phones". Phones send nothing: no hello, no heartbeat, no polling.
- **Messages.** One `{ v, type: 'public.state', seq, nowMs, state }` on connect (and when the Game changes), then `{ v, type: 'public.delta', seq, nowMs, changes }`, each `seq` one more than the last. `followFeed(view, message)` applies them with `applyPublic`. A gap, or a delta before any snapshot, answers `resync`: reconnect for a fresh snapshot, so a lost message never leaves a wrong card on screen.
- **Reconnecting.** When the socket closes: `reconnectDelayMs(attempt)` (full jitter, a ceiling of 1 s doubling to 30 s), so a crowd never comes back at once. Back in the foreground, only if the socket closed meanwhile, after up to `PUBLIC_FEED.resumeJitterMs`. Every connection is a billed request.
- **Time.** Every time is on the cloud's clock; `nowMs` lets a phone estimate its offset.
- **What `PublicState` holds.**
  - `edition` ('26'): phones keep their cards per edition.
  - `gameId`: a rehearsal and the night are different Games; a change resets the rounds shown, never the cards.
  - `scene`, `intro` (the round being introduced, `{ round, kind, cardType }`) and `shuffle` (its timing).
  - `rounds[]` for the whole Game: `{ number, kind, cardType, startedAtMs, lineConfirmed, ended, landings: [{ position, songId, atMs }] }`, counted landings only. A card counts in a round when `card.type === cardType`; from an older cloud without `cardType`, use `defaultCardType(kind)`.
  - `spin` (`startAtMs`, `landAtMs`; null `landAtMs` during a Suspense; never the song).
  - `heat`: display samples `{ value, fromMs, toMs }`, null until the engine emits them.
  - `check` (`{ round, cardId, kind, result: 'pending' | 'valid' | 'invalid' }`, never its steps).
  - `winners[]`: one entry per prize, `cardIds` shared.
  - `interval`, `pause` and `gameEndMs` (rounded to `PUBLIC_FEED.gameEndRoundingMs`).
  - `link` (the laptop's connection: show "Connexió perduda" after `PUBLIC_FEED.offlineNoticeAfterMs` offline).
  - `plan` (`GamePlan`, logos as asset paths).
  - `notice` (Admin's banner) and `soundsDefault`.
- **Never in it.** The Queue, `next`, `transition.to` before the landing (but `drum.targetId` is public from the Spin's start since U206, as `PublicSpin.targetId`, and screens reveal it only at the landing), `possibleWinners`, `future`, `hold.ducked`, `phase`, the real `heat`, `schedule.roundEndMs`, a Check's steps before its verdict, claims' `completeSince` and `warnings`, winners' names and notes, the journal.

## Analysis files

The Check starts each ✓ on `/snippets/<id>.flac` (`<cacheDir>/<id>/snippet.flac`, 3 s from the song's best hook's pickup) at the trim in `/data/snippets/index.json` (`tools/prep/snippets.py`, the prepare step `snippets`; its `startSec` places the snippet in the song), then plays on in the full song `/audio/<id>.flac` at that same trim.

The Interval playlist is global, like Hold music: `/data/interval/index.json` (the tracks in playlist order, the duplicates dropped and the entries without a file) and `/data/interval/<slug>.json` (title and artist from `playlist.spotdl`, beats, regularized downbeats, tempo, loudness, and the edges: where the sound starts and ends, where the closing fade starts, the first downbeat; schema v1, checked by `engine/src/interval/tracks.ts`), with the audio at `/intervalaudio/<slug>.flac` (`data/cache/interval/`, 48 kHz). The relay serves them whatever the repertoire.

The engine also checks the analysis JSON it loads (`data/out/analysis/<id>.json`, written by `tools/prep/analyze.py`, `schemaVersion: 1`) against `engine/src/analysis.ts`. A song whose file fails the check is left out of the round, or its decode is rejected and Hold music covers.
